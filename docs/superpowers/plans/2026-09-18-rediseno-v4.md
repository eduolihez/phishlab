# Rediseño v4 de interfaz — Plan de implementación

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Aplicar el sistema de diseño v4 (DESIGN.md, 2026-09-18) al código existente de PhishLab: tipografía autoalojada nueva, tokens de color con acento ámbar de señal, y motion con física de resorte en paneles/modales.

**Architecture:** Cambio puramente de presentación sobre `assets/css/app.css` (único fichero de estilos, sin build ni preprocesador) más dos ficheros de fuente nuevos en `assets/fonts/`. No se toca ningún fichero de `assets/js/` — la revisión del spec confirmó que la estructura de componentes (tarjetas lideradas por señal, pestañas del workspace) ya cumple el sistema v4, solo cambian los valores visuales que consume.

**Tech Stack:** CSS puro con custom properties (`:root`), `@font-face` con ficheros `.woff2` autoalojados, `node --test` para la suite existente. Sin dependencias nuevas.

**Spec:** [docs/superpowers/specs/2026-09-18-rediseno-v4-design.md](../specs/2026-09-18-rediseno-v4-design.md)

## Global Constraints

- PhishLab no depende de ningún CDN en tiempo de ejecución, ni siquiera para fuentes — todo `.woff2` se sirve desde `assets/fonts/` (ver spec, sección 1).
- Los nombres de las variables CSS existentes (`--acento`, `--fondo`, etc.) no cambian, solo sus valores — evita romper cualquier otro consumidor de esas variables.
- No se toca `assets/js/` ni la estructura DOM de ninguna vista.
- `demo/` y `lab/` son artefactos generados (`.gitignore`) — nunca se editan a mano, se regeneran con `npm run build:demo` / `npm run build:lab`.
- `npm test` (339 pruebas) debe seguir en verde al final de cada tarea.
- Contraste AA: texto normal ≥ 4.5:1, elementos interactivos grandes ≥ 3:1 (ver spec).

### Task 1: Descargar y autoalojar las fuentes nuevas

**Files:**
- Create: `assets/fonts/bricolage-grotesque.woff2`
- Create: `assets/fonts/geist.woff2`
- Test: ninguna (paso de infraestructura, verificado manualmente en Step 4)

**Interfaces:**
- Produces: dos ficheros `.woff2` en `assets/fonts/`, listos para referenciar desde `@font-face` en la Task 2.
- Consumes: nada.

- [ ] **Step 1: Descargar el CSS de Google Fonts para localizar las URLs reales de los ficheros woff2**

```bash
curl -s "https://fonts.googleapis.com/css2?family=Bricolage+Grotesque:wght@600;700&family=Geist:wght@400;500;600&display=swap" \
  -H "User-Agent: Mozilla/5.0 (Windows NT 10.0; Win64; x64) AppleWebKit/537.36" \
  -o /tmp/gfonts.css
cat /tmp/gfonts.css | grep -o 'https://fonts.gstatic.com/[^)]*\.woff2'
```

Nota: el `User-Agent` importa — sin uno moderno, Google Fonts devuelve `.ttf`
en vez de `.woff2`. El comando lista una URL por cada combinación de peso +
subconjunto de idioma (latin, latin-ext, etc.); para esta tarea basta con
descargar el subconjunto `latin`.

- [ ] **Step 2: Identificar y descargar el woff2 `latin` de cada peso**

El bloque de `latin` es el que no lleva un comentario `/* cyrillic */`,
`/* greek */`, etc. justo encima en el CSS. Para cada familia, descargar
**un solo peso representativo** (600 para Bricolage Grotesque como variable
si está disponible, si no 600 y 700 por separado; 500 para Geist, ya que
`--sans` se usa tanto en 400 como 500/600 vía `font-weight` en las reglas
existentes — confirmar en Step 3 si hace falta más de un peso):

```bash
# Sustituir <URL> por cada URL localizada en el Step 1
curl -s "<URL-bricolage-600>" -o assets/fonts/bricolage-grotesque-600.woff2
curl -s "<URL-bricolage-700>" -o assets/fonts/bricolage-grotesque-700.woff2
curl -s "<URL-geist-400>" -o assets/fonts/geist-400.woff2
curl -s "<URL-geist-500>" -o assets/fonts/geist-500.woff2
curl -s "<URL-geist-600>" -o assets/fonts/geist-600.woff2
```

- [ ] **Step 3: Verificar que los ficheros descargados son woff2 válidos, no HTML de error**

```bash
file assets/fonts/bricolage-grotesque-600.woff2 assets/fonts/bricolage-grotesque-700.woff2 assets/fonts/geist-400.woff2 assets/fonts/geist-500.woff2 assets/fonts/geist-600.woff2
```

Expected: cada línea dice `Web Open Font Format` (o similar), nunca
`HTML document` ni `ASCII text` — si alguno falla, la URL del Step 1 estaba
mal copiada o el `User-Agent` no se aplicó.

- [ ] **Step 4: Confirmar tamaño razonable (no un placeholder vacío)**

```bash
ls -la assets/fonts/bricolage-grotesque-*.woff2 assets/fonts/geist-*.woff2
```

Expected: cada fichero pesa entre 10 KB y 60 KB. Un fichero de 0 bytes o de
pocos cientos de bytes indica descarga fallida.

- [ ] **Step 5: Commit**

```bash
git add assets/fonts/bricolage-grotesque-600.woff2 assets/fonts/bricolage-grotesque-700.woff2 assets/fonts/geist-400.woff2 assets/fonts/geist-500.woff2 assets/fonts/geist-600.woff2
git commit -m "feat: autoalojar Bricolage Grotesque y Geist para el rediseño v4"
```

## Self-Review

**Cobertura del spec:** las 5 secciones de "Qué cambia" del spec
(tipografía, tokens, "nada cambia en componentes", motion, grano de fondo)
están cubiertas: Tasks 1-2 (tipografía), Task 3-4 (tokens + contraste),
Task 5 (motion). "Nada cambia en componentes" no genera tarea porque es
una confirmación de que no hay trabajo, no un entregable — correcto no
tener tarea para eso. El grano de fondo está explícitamente fuera de
alcance (landing pública) y no genera tarea aquí — correcto.

**Placeholders:** ninguno — cada `@font-face`, cada valor de color y cada
`@keyframes` está escrito literal en el paso correspondiente. La única
ambigüedad marcada explícitamente (contraste del botón primario) tiene
pasos concretos de cálculo y una decisión binaria, no un "TBD".

**Consistencia de nombres:** `--resorte` se define en Task 3 y se consume
en Task 5 sin cambiar de nombre; `--acento-rgb` se define en Task 3 y queda
disponible para cualquier tarea futura aunque esta ronda no lo consuma
directamente (documentado en el spec como utilidad, no como requisito de
esta ronda).
